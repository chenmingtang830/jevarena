## Reproduction and limits

Models were called sequentially from local Node through the production Gateway API, Jev first for each question. Each chat request had a 4,096 output-token ceiling, provider-default reasoning, and a 55-second application timeout. Public response fields were captured for offline inspection. DeepSeek reported 0 and 50 reasoning tokens respectively. Jev reported a choice probability of 1 and independent vendor confidence of 1 on both questions. Neither probability is evidence of global calibration.

Actual model revisions were not returned beyond request aliases, and remain unknown. Network warmup, routing, reasoning differences, fixed order, instrumentation, and n=2 prohibit a general speed/accuracy ranking. These two simple reference answers do not explore the difficult failure boundary. No Jev failure was found in this tiny canary.

The local key was read from `AI_GATEWAY_API_KEY` in process memory. It was not passed on a command line, printed, copied into a browser, exported, or committed. No production relay was enabled. This verifies the native Gateway evaluation path and one Gateway chat comparator only; OpenRouter, TypeSafe direct, deployed relay, and browser BYOK still need their own live acceptance.

## Defect discovered and fixed

The original adapter estimated Jev cost from list price and omitted independent confidence because it looked only at `usage.cost` and `answers.judgment.confidence`. Live Gateway responses put billed cost and confidence under provider metadata. The corrected parser preserves actual zero, rejects malformed cost strings, and does not confuse market cost with billed cost. Native Jev records also no longer claim the chat-only output-token cap, which was not sent to the evaluation API. Three offline regression tests cover these corrections. Original local receipt remains unchanged; the public projection is re-normalized offline without spending more.
