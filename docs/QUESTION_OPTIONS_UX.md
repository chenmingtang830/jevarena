# Question-and-options entry

The homepage has one task format: a question with any necessary context, followed
by editable possible answers. It does not ask visitors to choose a task type,
understand judge terminology, or select an Arena/Compare mode before starting.

Three examples populate the complete question and answer choices: a suspicious
email, a mathematical claim, and a comparison of two supplied answers. Examples
are editable templates, not measured results. Loading them never calls a model.

The first start action reveals the API-key field. Once a key is present, the
estimated two-call cost and an explicit start button are available. Filling a key
does not automatically start a paid request. Optional opponent and budget controls
remain behind Settings. Keys remain in tab memory only.

Existing structured comparison records retain their original schema and semantics
when opened for reproduction. The new homepage does not migrate or reinterpret
historical records. Labels, voting, cost checks, sharing consent, and research
contribution consent are unchanged.
